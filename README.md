# Автосид PHEX

Статическая страница PHEX показывает состояние двух серверов Squad и выбирает
точку общего сида по свежести данных, доступности и приоритету.

## Текущее состояние

| Часть | Состояние |
|---|---|
| Страница, фирменная тема и мобильная вёрстка | готово |
| Выбор между `phex-1` и `phex-2` | готово, проверено |
| Ванильный образ SquadJS с минимальным экспортёром | собран и опубликован в GHCR |
| Отдельный репозиторий `phex-squad/squadjs` | создан, сборка GitHub Actions успешна |
| Два сервиса Dokploy и HTTPS-маршруты | развёрнуты, RCON и CORS проверены |
| GitHub Pages | ожидает включения владельцем репозитория |
| RCON-пароли | перенесены напрямую в Dokploy, в Git не публикуются |
| Ключ SquadBrowser | ожидается от владельца |

Состояние и выбор сервера уже работают на боевых данных. До получения ключа
SquadBrowser кнопка входа честно сообщает о временной недоступности ссылки.

## Боевой контур

```text
GitHub Pages
    ├── GET snapshot ──> Dokploy / phex-1 ──RCON─> Squad №1
    └── GET snapshot ──> Dokploy / phex-2 ──RCON─> Squad №2

Кнопка входа ──> join-link экспортёра ──> SquadBrowser ──> steam:
```

Страница получает только публичные HTTPS-адреса. RCON-пароли, ключ
SquadBrowser, адреса и пути хоста остаются в Dokploy.

Контейнеры работают на основном узле Dokploy и подключаются к игровым серверам
по RCON. Доступ Dokploy к Docker или файловой системе игрового хоста не нужен.

## Структура

- [`site`](site) — содержимое GitHub Pages;
- [`docs/deployment.md`](docs/deployment.md) — порядок боевого выпуска;
- [`docs/variables.md`](docs/variables.md) — публичные параметры страницы;
- [`docs/troubleshooting.md`](docs/troubleshooting.md) — диагностика;
- `overlay/` и `deploy/` — сохранённый переносимый вариант для хоста без
  контейнеров; текущий боевой контур его не использует.

Серверный образ и его конфигурации вынесены в отдельный форк
`phex-squad/squadjs`.

## Проверка

```bash
npm test
```

Проверки не используют сеть и секреты. Они проверяют выбор сервера, поведение
при устаревших данных, отсутствие секретов в публичной части и поставку Pages.

## Публикация

1. Выполнить `npm test`.
2. Владелец репозитория выбирает `Settings → Pages → GitHub Actions`.
3. Повторно запустить процесс публикации и проверить
   `https://phex-squad.github.io/autoseed/`.

## Безопасность

- браузер не получает ключ SquadBrowser или RCON-пароль;
- публичный снимок не содержит SteamID, EOSID и IP игроков;
- экспортёры разрешают CORS только странице Phoenix;
- кнопка подключения принимает только адрес со схемой `steam:`;
- конкретная схема хоста не публикуется в этом репозитории.
